# 吉星派对 Mod 工坊

工坊采用「软件内上传 → 安全检查 → 人工审核 → 发布目录」流程。上传者无需 GitHub 账号；维护者使用 GitHub Issue 和 Actions 审核，没有独立管理员网页。客户端只下载本仓库 GitHub Release 中、已经审核并登记 SHA256 和大小的资源 ZIP。目录发布在本仓库 `workshop` 分支根目录的 `catalog.json`；本文件夹提供初始目录与维护说明。首次启用目录为空，不用测试包冒充玩家作品。

1.3.4 已接入公网上传服务与 GitHub 审核；真实上传、同步、拒绝和重启状态查询通过验证，实际作品的批准上架与撤回还需游戏实测。服务未开通或无法确认健康状态时，客户端会停止上传。部署与审核工具见[上传服务说明](../workshop_service/README.md)。

维护者在 GitHub 查看审核单；待审 ZIP 不公开到 Issue 或 Actions 下载附件。本机取包使用 `python -B tools/workshop_fetch_review.py <投稿编号> --output <全新的审核ZIP路径> --ssh-alias killer-star`，需要维护者自己的 SSH 权限。取包先进行服务器杀毒，再检查结构与摘要，仍需 Windows Defender 扫描和实际游戏验证。工作流每小时同步待审作品；可运行 `sync` 立即同步。填写审核结论时请使用实际测试记录，不能用“自动检查通过”代替游戏验证。

## 作者投稿

在助手「Mod 工坊」展开「分享我的作品」，选择资源替换 ZIP、填写名称和介绍，点击「上传作品」。作者、分类和版本为折叠可选项。确认上传后会显示投稿编号和「待人工审核」，可在「我的投稿」刷新状态。ZIP 和介绍会发送到工坊服务器；投稿者不用注册 GitHub，也不用手动上传附件或提交 Issue。

单个上传 ZIP 上限为 **80 MiB**，界面以服务返回的当前限制为准。**制作工具不限**，其他工具制作的兼容 `.bundle` ZIP 也能投稿，不需要先导入助手作品集。缺少根目录 `mod_info.json` 时，会按填写的信息自动生成；如果包内已有描述文件，仍须通过格式检查。资源文件名须对应当前游戏资源。版本信息可选，未填写的游戏版本标为「未标注」，维护者仍需验证实际适用版本。

网络失败时可以重试，选中的 ZIP 和介绍会保留。本地副本导出只保存到本机，不算上传。上传成功不等于审核通过，也不会立即上架。待审核包保存在服务隔离区，GitHub Issue 只用于查看投稿说明和审核记录，不公开附上待审核 ZIP。

只分享原创修改所需的资源包，不能上传整份游戏、账号数据或私人信息。投稿包仅支持 `.bundle`、根目录 `mod_info.json`、根目录 `emote_addresses.json`；程序、脚本、快捷方式和其他附件会被拒绝。封面、评论、自动订阅留待后续版本。

## 维护者上架

1. 在仓库 **Issues** 查看对应投稿，核对说明、投稿编号与安全检查结果。取得待审核包的方法见[上传服务说明](../workshop_service/README.md)；不要运行投稿者附带的程序。
2. 确认病毒扫描通过，在隔离目录检查内容，并使用资源副本和对应游戏版本验证实际效果。保留游戏版本、验证步骤、截图或录像等证据。自动检查通过不能当成游戏验证，也不能保证安全。
3. 打开 **Actions → Workshop Review → Run workflow**。选择 `approve` 时填写实际测试的游戏版本、验证证据和至少 20 字的详细审核说明。没有游戏测试证据不能批准。拒绝选择 `reject`，并说明原因。
4. 批准流程会将已审核包发布到本仓库的工坊 Release 并更新目录；作品才会出现在客户端。流程失败时先检查错误，不要把「上传成功」当成「已上架」。工坊包使用独立标签，不触发助手自身正式版本发布。
5. 保存审核 Issue、扫描与游戏验证记录。发现可疑内容时，运行同一工作流选择 `revoke` 并填写原因，撤回目录条目。必要时移除 Release 资产。

下载和确认安装都会重新获取线上目录；目录不可达、被撤回、摘要变化或游戏资源不匹配时停止安装。Windows Defender 无法扫描或扫描报错时也停止自动安装。已经安装的作品不会因下架自动卸载；请使用 Mod 管理禁用或还原，并通知受影响用户。

## 防护边界

客户端拒绝路径越界、Windows 特殊路径、重名覆盖、符号链接、压缩炸弹及可执行附件，限制网络来源、下载与解压大小，核对 SHA256，并在安装前再次核验解压内容。它只替换游戏资源，沿用现有备份与还原流程。

资源包内部也会检查：有界展开 UnityFS 并核对 serialized 对象表，拒绝内嵌 PE、程序集 TextAsset，以及当前游戏 catalog 中的程序集承载包目标。投稿、审核、下载和安装前复核共享此检查；未知格式、内部超限或无法确认时停止操作。检查不会加载或执行程序集，这些防护适用于工坊链路，不能代替人工审核或防病毒扫描。

这些措施不能保证零风险。摘要只证明下载内容与审核记录一致；Unity 资源解析器仍可能存在漏洞，维护者账号或可信目录被攻破也会影响信任。保护维护者 GitHub 账号（包括双重验证）、保留审查记录、及时更新工具与系统防病毒保护仍然必要。客户端没有远程脚本或管理员密钥。
