# 吉星派对 Mod 工坊

工坊采用人工审核目录。客户端只下载本仓库 GitHub Release 中、已由维护者登记 SHA256 和大小的资源 ZIP。目录发布在本仓库 `workshop` 分支根目录的 `catalog.json`；本文件夹提供初始目录与维护说明。首次启用目录为空，不用测试包冒充玩家作品。

## 作者投稿

在助手「Mod 工坊」展开「分享我的作品」，选择资源替换 ZIP、填写作品说明，导出投稿包与旁边的 JSON 审核报告。**制作工具不限**，其他工具制作的兼容 `.bundle` ZIP 也能投稿，不需要先导入助手作品集。缺少根目录 `mod_info.json` 时，导出投稿包会按填写的信息自动生成；如果包内已有描述文件，仍须通过格式检查。资源文件名须对应当前游戏资源。点击「打开投稿页」，登录自己的 GitHub 后手动附上这两个文件并提交 Issue。较大文件可放在作者自己的 GitHub Release，在 Issue 提供链接。助手不保存作者 GitHub 密钥，也不会自动把投稿上架。

只分享原创修改所需的资源包，不能上传整份游戏、账号数据或私人信息。投稿包仅支持 `.bundle`、根目录 `mod_info.json`、根目录 `emote_addresses.json`；程序、脚本、快捷方式和其他附件会被拒绝。封面、评论、自动订阅留待后续版本。

## 维护者上架

1. 下载到隔离目录，使用 `tools/workshop_review.py inspect` 检查 ZIP。不要运行任何投稿者附带的程序。
2. 在开启防病毒保护、已更新病毒库的电脑扫描 ZIP 与解压资源。审查作者来源、修改内容和游戏版本，使用资源副本做兼容性测试。不要仅凭摘要校验判定安全。
3. 审核通过后，把原样 ZIP 上传到**本仓库**单独的 Release，例如 `workshop-example-v1`。不要使用 `v*` 标签，避免触发助手自身正式版本发布工作流。
4. 用 `python tools/workshop_review.py entry author-pack.zip --metadata author-pack.submission.json --tag workshop-example-v1 --output candidate.json` 生成条目，初始 `revoked` 为 `true`。全部审核完成后人工改成 `false`，将结果合并到 `workshop` 分支的 `catalog.json`。名称、文件大小与 SHA256 必须对应实际 Release 资产，不得修改包后复用旧摘要。维护命令只生成本地文件，不会自动上传或上架。
5. 保存审核 Issue、扫描与兼容性验证记录。出现可疑内容时，立即在目录将该条目标为 `"revoked": true` 并提交，必要时移除 Release 资产。

下载和确认安装都会重新获取线上目录；目录不可达、被撤回、摘要变化或游戏资源不匹配时停止安装。Windows Defender 无法扫描或扫描报错时也停止自动安装。已经安装的作品不会因下架自动卸载；请使用 Mod 管理禁用或还原，并通知受影响用户。

## 防护边界

客户端拒绝路径越界、Windows 特殊路径、重名覆盖、符号链接、压缩炸弹及可执行附件，限制网络来源、下载与解压大小，核对 SHA256，并在安装前再次核验解压内容。它只替换游戏资源，沿用现有备份与还原流程。

资源包内部也会检查：有界展开 UnityFS 并核对 serialized 对象表，拒绝内嵌 PE、程序集 TextAsset，以及当前游戏 catalog 中的程序集承载包目标。投稿、审核、下载和安装前复核共享此检查；未知格式、内部超限或无法确认时停止操作。检查不会加载或执行程序集，这些防护适用于工坊链路，不能代替人工审核或防病毒扫描。

这些措施不能保证零风险。摘要只证明下载内容与审核记录一致；Unity 资源解析器仍可能存在漏洞，维护者账号或可信目录被攻破也会影响信任。保护维护者 GitHub 账号（包括双重验证）、保留审查记录、及时更新工具与系统防病毒保护仍然必要。客户端没有远程脚本或管理员密钥。
