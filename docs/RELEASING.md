# 发布新版

修改 `astral_party_auto/__init__.py` 中的版本，并同步 Changelog、发布说明和使用文档。版本格式为三段数字，可附预发布标识，如 `1.3.12-preview.1`。

合并到 `main` 后，Build and Release 会依次完成安全检查、Windows 构建和打包。通过后，发布任务使用同一次构建的 ZIP、SHA256SUMS 和 RELEASE_NOTES 创建对应版本标签及 Release。预发布版本会标为 prerelease。

已有标签指向别的提交或正式 Release 已存在时，主分支任务保留它们，不移动标签或覆盖资产。不变更版本的普通合并只生成构建产物。手动推送与源码版本相同的标签仍可使用原有发布入口。

发布请求必须来自本仓库可信的主分支或匹配版本的标签 push。标签查询只有明确的 HTTP 404 才视为不存在；认证、网络或未知状态会停止发布。

如果标签已由同一次构建创建、但 Release 尚未创建，可以重跑失败的发布任务：确认标签仍指向本次提交后，会继续发布同一份 artifact。若发现草稿或状态不明，流程停止，保留已有资产供维护者检查，不自动覆盖。

正式发布后核对标签提交、Release 的公开状态、ZIP 大小与 SHA256、内嵌版本。构建与静态检查不代替真实游戏效果验收。
